# CLI output playground

The playground is an interactive HTML terminal backed by the real `cmd/notte`
binary and a loopback fixture API. Both generic and command-specific formatting
come from the CLI. The browser renders its stdout and stderr with ANSI colors.

## Start iterating

From the repository root, run:

```sh
make ui-preview
```

Open <http://127.0.0.1:4173>. Use `make ui-preview UI_ADDR=127.0.0.1:4174` to
choose another port. Go is the only development dependency.

Type `notte`, then press Enter for CLI help. Try:

```sh
notte sessions start
notte sessions list
notte sessions status
notte page observe
notte page scrape
notte page scrape --instructions "Extract product names and prices"
notte sessions list --output json
notte sessions stop
```

Use Up/Down for command history, Tab for completion, and `clear` or Ctrl+L to
clear the terminal. Quotes and escaped arguments are supported. `--no-color`
and `--output json` are actual CLI flags. This is a fixture sandbox, not a shell;
it supports help, version, the session commands above, and page observe/scrape.
Each invocation uses a fresh synthetic session, so it does not model a persistent
browser lifecycle. Unsupported commands produce a playground diagnostic.

Edit Go code and save. Changes under `cmd/` and `internal/`, the fixture JSON,
and `go.mod`/`go.sum` rebuild the CLI and replay the visible commands. Typed input
and history survive page reloads. The viewer does not emulate a PTY or terminal
width detection. Verify final wrapping and colors in an actual terminal.

The first build can take longer while Go downloads modules. Later rebuilds use
the normal Go build cache. If the build or a scenario fails, the page marks the
last successful results as stale and shows the error. Fix the source and save
again to regenerate. Changes to the playground server itself require restarting
`make ui-preview`; formatter, command, fixture, and HTML edits refresh automatically.

## Iterating with an assistant

Leave the local server running and the playground open. For example:

> In the CLI playground, make session status show the session ID and status
> first, then put the connection links together. Keep the JSON output stable.

The assistant should edit the actual output code and inspect the refreshed
terminal transcript. Fixture `source` fields identify the relevant Go files.
When adding new output behavior,
add a representative fixture and a focused test. Check the full CLI command
before shipping, including its stdout/stderr and exit code.

Generic text rendering lives in `internal/output/text.go`. Command-specific
rendering lives in `internal/cmd/`, including `output_helpers.go`. The viewer
is `internal/playground/web/index.html`; change it for playground controls and
presentation, while keeping terminal contents generated by the CLI.

## Add a scenario

Edit `internal/playground/scenarios.json`. Each scenario supplies:

- A unique `id`, `group`, `title`, and `description`.
- `args`: actual CLI arguments, without the `notte` executable. Supply an
  explicit `--session-id` when a command needs one.
- `source`: the relative Go source path to edit for this output.
- `expectedExit`: normally `0`, or `1` for a deliberate error example.
- `responses`: exact API URL paths, HTTP statuses, and synthetic JSON bodies.

The runner adds `--yes`, records text, forced ANSI color, and JSON variants, and
validates exits and API paths. Root/group help and version need no API responses.
Use demo IDs, example.com URLs, fixed timestamps, and synthetic content. Fixtures
are included in public static exports.

Every command gets its own temporary working directory, home and config, a fake
API key, a loopback API URL, and disabled update checks. Saved credentials,
current sessions, proxy variables and other Notte environment variables are not
inherited. Interactive requests execute allowlisted Notte commands directly,
without a shell. Authentication, installers, upgrades and file commands do not run.

## Static docs or demo

```sh
make ui-export
python3 -m http.server 4174 --directory dist/ui-playground
```

Open <http://127.0.0.1:4174>. The export contains only `index.html` and
`preview.json`, with no backend, npm dependencies, or credentials. Static
exports match typed commands to recorded fixture results. They represent the
captured revision and do not run a CLI or watch your working tree. Serve them
over HTTP rather than opening a file URL.

Set `UI_EXPORT_DIR` to change the destination. Exporting does not publish the
site or change the CLI's existing human or JSON output.

## Validate

```sh
go test -race -short ./internal/playground ./internal/output ./internal/ui ./internal/cmd
```

The playground tests exercise actual CLI subprocesses against the synthetic
API, validate isolation, and check HTTP/export behavior. Existing formatter
tests remain the place to lock in an approved layout.
